# Contract: `.spaex/constitution.md` format version 2

Replaces [023 `spaex-md-format.md`](../../023-behavior-harness/contracts/spaex-md-format.md) for `version="2"`. Version 1 stays documented there as history; spaex only writes version 2.

## Header and notices

```markdown
<!-- spaex-composed:source_hash="<sha256-hex>" build_input_hash="<sha256-hex>" version="2" -->
# spaex Behavior Harness

_This file is generated by `spaex install`. Do not edit by hand._
_Change fragments in `.spaex/constitution.d/` and re-run install. Text inside a comment marked `spaex-excluded` is not an instruction._
```

- `source_hash`: unchanged from spec 023 (canonical records of all fragments).
- `build_input_hash`: sha256 of the check prompt version, the effective check prompt hash and the valid decisions (key and choice, sorted by key).
- Spec 029 preamble, when present, follows the notices as today.

## Fragment blocks

Blocks follow in the order of their scoped id (the order `composer/invoke.py` already sorts by). One blank line between blocks, one trailing newline at the end of the file.

```markdown
<!-- spaex-fragment id="<molecule-id>/<fragment-id>" modality="<MODALITY>" -->
<fragment body, unchanged>
<!-- /spaex-fragment -->
```

- `modality` appears only when the fragment declares one.
- The body is the fragment body after the normalization spec 023 applies for hashing (line endings LF, no trailing blank lines). Nothing else is changed.
- The `<!-- spaex-` prefix cannot occur inside a body (spec 023 rejects it), so block boundaries are unambiguous.

## Excluded passages

A passage the operator did not keep stays at its place, replaced by one comment:

```markdown
<!-- spaex-excluded kept="<molecule-id>/<fragment-id>:<start>-<end>" decision="<key-prefix-12>"
<the passage lines, unchanged>
-->
```

- `kept` names the passage that was kept (several, comma-separated, if more than two passages were involved and one was kept).
- The comment ends at the first line that is exactly `-->`. A `-->` that occurs inside the excluded text is written as `--&gt;`; this is the only change to text, and only inside an exclusion.
- Overlapping exclusions are merged into one comment.

## Empty set

No fragments: the file is absent (spec 023 FR-017d), as before.

## Parsing

`render.parse(text)` returns the header fields, the blocks (scoped id, modality, body lines with their line numbers in the file) and the exclusions (line range in the file, kept reference, decision prefix). `render.verify` uses it (R2); `trace` and `status` use it (R11, R12). There is no clause regex in version 2.
